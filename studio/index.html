Protect head + arm + torso from jaw MP3 RECOMMENDED

Skelly's MP3 appears to reset movement flags when playback starts. When ON, let the current head, arm or torso movement finish before playing an MP3; postpone new standalone body movement until the jaw clip is done. Jaw-first arm/torso follow-ups remain allowed. This overrides the independent Head + Jaw overlap switch so the head isn't cut off. Jaw events may start later than their target.

OFF = one successful diagnostic run per BLE connection. ON = coordinated recurring movement: the arm or torso waits until its configured interval has elapsed, then starts after the next jaw MP3. Not every jaw clip triggers a motor. Recurring mode needs extended testing.

Confirmed: jaw-first arm and jaw-first torso commands work on this Skelly. Alternate arm or torso is a new option that requires both motors enabled and recurring mode ON. Each motor waits for its own random interval; when both are due, the controller prefers the motor it didn't send last time. Only one motor is sent after a jaw MP3, subject to cooldown and body lock. Start by testing with Head OFF. Read the test guide.

Allow body motor overlap ADVANCED / UNTESTED

Allow head, torso and arm animations to run at the same time. Each still has its own cooldown, and commands are spaced by 600 ms. OFF in all presets until combinations are tested.

Allow independent head + jaw overlap

Only applies when MP3 body protection is OFF. On this Skelly, playing an MP3 during a head animation appears to interrupt it. Keep protection ON until jaw-first head movement is separately tested.

  1. Open the file in Arduino IDE using ESP32 Dev Module.
  2. Power on Skelly, and close any other Bluetooth controller.
  3. Upload to your ESP32 and open Serial Monitor at 115200.
  4. If it doesn't connect after flashing, try the board's EN/RESET button; scan retry happens automatically.
